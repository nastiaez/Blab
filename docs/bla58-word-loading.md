### Device cache/privacy contract
- Short data is optional device-local SharedPreferences under cached_short_meanings_v1:<account>. Per-account maximum128 entries and256KiB UTF-8 serialized JSON (keys, timestamps and values included); oldest-write-first eviction. Oversized entries are not retained. Entries expire after30days; expired data is ignored on read and pruned on the next short write. No background deletion.
- Stored key is SHA-256 of the exact mode/version, account, message ID, complete selected/accepted sentence, complete source, historical revision, both languages and UTF-16 start/end tuple. No word-text-only lookup, cross-context reuse or raw sentence storage. Only meaning plus timestamp is persisted; full detail fields are not stored. Missing historical revision permits a short request but disables durable reuse, rather than assuming an era.
- This uses the existing app-local preference security boundary, not a claim of application-level encryption. Meanings themselves can contain private context. Logout closes the service, clears full in-memory data and fences in-flight results; short data remains under its account namespace for same-account offline reuse and cannot be read by another account. Account deletion explicitly erases only that account short store, generation-fences queued writes and leaves other accounts intact. Message edits/language changes use different exact keys; old optional meanings become unreachable and age/evict normally, never rewrite history. Removing app data removes the local store. No bulk cache invalidation.
- Full details remain memory-only at the existing128-entry maximum, additionally bounded to1MiB UTF-8 serialized key+value bytes. Closing account scope drops memory; no new durable full cache. In-flight requests coalesce separately by exact context/mode. Cache persistence failure does not discard an otherwise valid meaning; corruption is a miss, never a false ready package.
