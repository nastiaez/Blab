## Finding confirmation

Current behavior:

- The repository has no `.github/workflows` configuration, so pull requests
  and main-branch changes are not required to pass formatting, analysis, tests,
  local backend integration, or an Android release compile.
- The suite has grown from the audit's 66 tests to 200 passing Flutter tests
  plus 11 passing local Supabase integration tests, but these gates run only
  when a developer invokes them.
- Before implementation, `flutter analyze` exited nonzero for two unused-code
  findings.
- Release builds correctly fail closed without ignored Firebase and signing
  files. CI therefore needs disposable non-production fixtures; real upload
  signing and hosted credentials must not be exposed to pull-request jobs.
- Local backend tests already use disposable Alice/Bob/Carol accounts, enforce
  allow/deny RLS cases, and pin Supabase CLI 2.109.1, but no clean Linux runner
  proves that setup remains reproducible.

Evidence:

- Audit: `tasks/mvp-launch-audit-2026-07-15.md`, P2 quality gaps and recommended
  launch gate 4.
- Workflow inventory: no tracked `.github` directory or CI provider config.
- Tests: `test/integration`, `test/local_readiness`, and
  `scripts/local_test.sh`.
- Release boundary: `android/app/build.gradle.kts`,
  `scripts/setup_android_signing.sh`, and ignored environment/Firebase files.
- Current verification: L-20 records 200 Flutter tests and 11 local backend
  integration tests passing, with two pre-existing analyzer warnings.

## Decision record

Required decision: None. GitHub Actions matches the repository/PR platform.

Engineering constraints:

- Pull-request CI must be non-deploying, use read-only repository permissions,
  and work without repository secrets, hosted Supabase projects, production
  identifiers, paid AI calls, or owner signing material.
- The Android release gate is a compile/packaging test, not a distributable
  build. It uses an ephemeral keystore and a clearly synthetic Firebase fixture.
- Production-signed builds and live provider checks remain explicit owner-run
  release gates because they carry credentials, cost, and deployment risk.

Approved decision: Use secretless GitHub Actions with quality, disposable local
Supabase integration, and non-deployable Android release-compile jobs.

Approved by/date: Engineering default for L-20 scope / 2026-07-22

## Scope

In scope:

- Add a GitHub Actions workflow for pull requests, pushes to `main`, and manual
  dispatch with minimal permissions and stale-run cancellation.
- Pin Flutter 3.44.4, Java 17, and Supabase CLI 2.109.1 to match the verified
  local toolchain.
- Gate Dart formatting, shell syntax, analyzer cleanliness, Flutter tests, and
  diff whitespace.
- Run the full disposable local Supabase reset, Realtime readiness probe, and
  integration suite on a clean Linux runner.
- Compile an Android release AAB with temporary CI-only signing and synthetic
  Firebase configuration, then destroy temporary credentials.
- Remove the two existing analyzer findings so the analyzer can be a strict
  blocking gate.
- Add source-contract tests preventing CI from acquiring production/staging
  credentials or accidentally deploying.

Out of scope:

- Deployment to Supabase, Firebase, Vercel, Sentry, Google Play, or any hosted
  environment.
- Real production upload/Play signing material in GitHub secrets.
- Paid OpenRouter translation calls in untrusted pull-request CI.
- Physical-device, Play-signed App Link, Google OAuth, push-delivery, startup,
  and ANR checks; these remain L-04/L-23 release gates.
- Dependency upgrades and Flutter's future Built-in Kotlin migration.

Files/systems expected to change:

- `.github/workflows/ci.yml`, CI-only Android fixture/helper, analyzer cleanup,
  CI contract tests, and launch records.

Migration, rollout, or rollback concerns:

- CI does not access or mutate hosted data. Local Supabase runs in disposable
  Docker services on the GitHub runner and is stopped even after failures.
- The synthetic AAB must never be uploaded or distributed. The workflow stores
  test coverage only and leaves release artifacts on the ephemeral runner.
- Rollback removes the workflow/helper/fixture; no application or hosted state
  changes are involved.

## Implementation record

Summary:

- Added a secretless, non-deploying GitHub Actions workflow with independent
  quality, disposable local Supabase integration, and Android release-compile
  jobs.
- Added a CI-only Android release helper that generates temporary signing,
  installs a synthetic Firebase configuration, compiles an AAB, and removes all
  temporary credential files through an exit trap.
- Removed the two analyzer findings and made formatting, analysis, all Flutter
  tests, shell syntax, whitespace, backend integration, and release compilation
  blocking checks.
- Added CI source-contract tests preventing hosted credentials, production or
  staging references, deployment commands, synthetic AAB upload, and missing
  clean-checkout Gradle wrapper files.

Files/migrations/configuration changed:

- `.github/workflows/ci.yml`
- `config/ci/google-services.json`
- `scripts/ci_android_release.sh`
- `test/ci_contract_test.dart`
- `android/.gitignore`, `android/gradlew`, `android/gradlew.bat`, and
  `android/gradle/wrapper/gradle-wrapper.jar`
- Analyzer/format cleanup in `lib/features/profile/change_email_screen.dart`,
  `test/word_popup_test.dart`, `test/first_message_empty_state_test.dart`, and
  `test/share_invite_sheet_test.dart`
- `tasks/launch/backlog.md` and this work record

Security/privacy review:

- CI has only `contents: read`, contains no secrets or hosted environment
  references, and cannot deploy. The local backend uses disposable Docker data.
- Android signing and Firebase files are synthetic, removed on exit, and the
  resulting non-distributable AAB is not retained as an artifact.

Operational or documentation changes:

- CI runs automatically on pull requests and `main`, can be manually dispatched,
  cancels stale same-ref runs, and bounds each job with a timeout.
- Flutter 3.44.4, Java 17, and Supabase CLI 2.109.1 are pinned. Future Flutter
  Built-in Kotlin migration remains explicitly outside this item.
