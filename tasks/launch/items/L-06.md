## Finding confirmation

Current behavior:

- Typing-indicator and read-receipt choices are persisted only in local
  preferences; neither setting currently guards a transport.
- Incoming-message visibility always queues and writes `message_reads` rows,
  including while Read receipts is OFF.
- The client always subscribes to and displays partner read rows, including
  while Read receipts is OFF.
- No typing-indicator transport or UI state exists, so its switch controls
  nothing.
- Preference hydration starts both switches at ON before an asynchronously
  persisted OFF value is loaded. A cold-start event can therefore escape
  before the privacy choice is known.
- The chat header labels the partner `Online` based on this device's network
  connectivity. This is false and conflicts with US-040's explicit ban on an
  Online/Last seen feature.

Evidence:

- Product requirements: [`US-040`](../../prd-blab.md#us-040-typing-indicators-signal-symmetric-toggle) and [`US-041`](../../prd-blab.md#us-041-read-receipts-toggle-signal-symmetric)

## Decision record

Required decision: `Use private Supabase Realtime Broadcast or Presence for ephemeral typing events?`

Options and tradeoffs:

- **Private Broadcast (recommended):** sends transient, non-persisted typing
  events over one authorized channel per active chat. It matches Supabase's
  event-oriented primitive, permits explicit start/stop and throttling, and
  avoids treating typing as durable user presence. This is a narrow deviation
  from the PRD line that names Presence, but not from its observable behavior.
- **Private Presence:** follows the PRD's named primitive exactly. Presence is
  intended to synchronize participant state and Supabase cautions against
  high-frequency updates, so the client would still need throttling and expiry
  around Presence payload updates.

Approved decision: `Use private Supabase Realtime Broadcast channels for
ephemeral typing events.`

Approved by/date: `Aswin, 2026-07-16`

## Scope

In scope:

- Persist both privacy choices without transmitting while their cold-start
  value is unknown.
- Gate read-receipt writes immediately before the Supabase mutation and gate
  partner-read subscriptions/display while OFF.
- Implement authorized, ephemeral typing transport with a 300 ms start delay,
  bounded update frequency, and a 3 s inactivity expiry.
- Gate typing sends, subscriptions, and display while OFF.
- Show partner typing in the active chat header and chat-list preview when the
  local control permits it.
- Remove the false Online label and restore the learning-language subtitle as
  required by US-040.

Out of scope:

- Online status, Last seen, or durable typing rows.
- Cross-device synchronization of a user's local privacy preferences.
- Retraction of read receipts written before the user disabled the control.
- Read-receipt table-policy tightening tracked by L-08.

Files/systems expected to change:

- Privacy-setting state and Privacy screen.
- Read-receipt state and focused tests.
- A typing transport/state module, chat input/header/list integration, and
  focused tests.
- A Supabase migration authorizing chat members on private typing channels.
- This work record and the launch backlog.

Migration, rollout, or rollback concerns:

- The Realtime policy must accept only authenticated members of the chat named
  in the private channel topic.
- The app must remain usable if a typing channel cannot subscribe; typing is
  best-effort and message delivery remains independent.
- Old clients have no typing transport and continue to interoperate.

Manual test steps:

1. Set both controls ON for both accounts, open the same chat, and type for
   longer than 300 ms without sending.
   Expected: the other account sees `typing...`; it clears within 3 s after
   typing stops, and no Online label appears.
2. Turn Account A Typing indicators OFF, then type from A and B.
   Expected: B never sees A typing, and A never sees B typing.
3. With Read receipts ON for both, open an unread message on Account A.
   Expected: Account B's delivered indicator changes to read.
4. Turn Account A Read receipts OFF, send a new message from B, and open it on
   A.
   Expected: B remains at delivered and A does not display partner-read state.
5. Force-stop and reopen Account A while both controls remain OFF, immediately
   open the chat, scroll messages, and type.
   Expected: the switches remain OFF and neither event is transmitted or
   displayed during startup.
6. Turn both controls back ON.
   Expected: new typing and read events work again without restarting.

Regression checks:

1. Messages still send and arrive live while either privacy control is OFF.
2. Offline banner and queued-send behavior still use local connectivity.
3. Previously stored read rows reappear only after Read receipts is turned ON.

## Implementation record

Summary:

- Privacy settings now load fail-closed and expose transport-facing enabled
  values only after persistence is known.
- Read receipts check privacy before queuing and immediately before the write;
  OFF also avoids the partner-read subscription and read UI.
- Typing uses an ephemeral private Broadcast channel per chat, a guarded send
  callback, 300 ms start delay, one-second heartbeat, and three-second expiry.
- The active chat header and visible chat-list tile show partner typing only
  while the local symmetric control is ON.
- False partner Online/Offline state derived from local connectivity was
  removed; the local offline banner and queued-send behavior remain intact.
