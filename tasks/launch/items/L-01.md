## Finding confirmation

Current behavior:

- `pair_with_email` is a `SECURITY DEFINER` RPC granted to authenticated callers.
- Any signed-in caller who knows an account email can create a chat containing that account without the recipient accepting an invite.
- The development menu exposes this RPC through a pair-by-email sheet.
- `chats_insert_self` allows any authenticated caller to create chat rows directly.
- `chat_members_insert_self` allows any authenticated caller to add their own user ID to any known chat UUID without an invite claim.
- A used invite can expose its `resulting_chat_id`, making the direct membership policy a practical unauthorized-join path for anyone who obtains that invite token.

## Decision record

Required decision: `None. The approved product contract is invite-only and requires recipient acceptance.`

Approved decision: `Only validated SECURITY DEFINER invite RPCs may create chats and insert chat memberships. Authenticated clients receive no direct INSERT privilege on chats or chat_members.`

Approved by/date: `Derived from approved launch workflow and invite-only product contract, 2026-07-15`

## Scope

In scope:

- Drop the `pair_with_email(text, text, text)` database function.
- Revoke authenticated and anonymous direct INSERT privileges on `chats` and `chat_members`.
- Drop the direct chat and self-membership INSERT policies.
- Remove `pairWithEmail` from the Flutter service API.
- Remove the development pair sheet and its development-menu entry.
- Add a database contract test for the removed function, privileges, policies, and retained `claim_invite` execution path.

Out of scope:

- Remove the rest of the development menu; tracked by L-02.
- Change invite persistence/resume; tracked by L-03.
- Deduplicate chats for repeat invitations; tracked by L-11.
- Tighten unrelated message/profile/read RLS policies; tracked by L-08.
- Deploy directly to production without an authorized deployment and rollback plan.

Files/systems expected to change:

- `supabase/migrations/`
- `supabase/tests/database/`
- `lib/shared/services/chat_service.dart`
- `lib/app/dev_menu.dart`
- `lib/app/dev_pair_sheet.dart` (delete)
- Focused tests and this launch record

Migration, rollout, or rollback concerns:

- Existing chats and memberships remain unchanged.
- Old client builds that call `pair_with_email` will receive an RPC-not-found error; this is intentional because the operation is unsafe.
- Apply the migration before external distribution. Removing only the Flutter UI would leave the RPC exploitable through the Supabase API.
- Rollback must not restore the consent bypass. Test accounts should pair through real invite claims.
