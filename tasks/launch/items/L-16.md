## Finding confirmation

Current behavior:

- A chat initially fetches only its newest 50 messages and offers no way to load older history.
- The Supabase table stream starts with a full chat snapshot and retains subsequent rows, so realtime memory and snapshot work grow with the chat.
- Translation hydration first queries every eligible message in the chat instead of only the messages loaded by the current page.
- Connectivity treats any active network interface as online. Wi-Fi without working Internet can therefore classify a retryable network failure as a permanently failed send.

Evidence:

- Deployed state: not required; L-18 owns production environment verification.

## Decision record

Required decision: None. Pagination and retryable offline behavior are existing launch requirements, and the implementation can preserve the current UI contract.

Options and tradeoffs:

- Use a deterministic `(created_at, id)` cursor rather than offsets so new arrivals cannot shift or skip older pages.
- Subscribe to individual database changes and merge them into loaded pages rather than receiving a growing table snapshot.
- Treat the configured Supabase backend as the relevant reachability target; an interface alone is not sufficient for this app to send.

Approved decision: Not applicable.

Approved by/date: Not applicable.

## Scope

In scope:

- Fetch the newest 50 messages initially and load older 50-message pages as the user scrolls upward.
- Deduplicate and deterministically order messages across page and realtime races.
- Hydrate cached translations only for newly loaded message IDs and request live translations only for eligible loaded messages.
- Replace full-snapshot message realtime with event deltas and resync the bounded loaded window after reconnect.
- Verify backend reachability and leave sends pending when Wi-Fi exists but Supabase cannot be reached.

Out of scope:

- Search, jump-to-date, media messages, server-side archival, or arbitrary offline history browsing.
- Notification delivery (L-17), production environment separation (L-18), and database-provider scaling changes.
- Redesigning message bubbles or translation rules established in L-15.

Files/systems expected to change:

- Chat service, chat state, translation state, connectivity state, chat list UI, dependencies, and focused Flutter/integration tests.

Migration, rollout, or rollback concerns:

- No schema migration is expected. Existing RLS remains authoritative for page queries and realtime events.
- Realtime channels must be removed on disposal to avoid leaked subscriptions.
- Rollback restores the prior snapshot stream but also restores the confirmed scaling and incomplete-history defect.

## Implementation record

Summary:

- Added deterministic `(created_at, id)` cursor pages with a 50-message page size and automatic upward-scroll loading.
- Replaced the growing Supabase table snapshot with individual insert/update/soft-delete events plus a bounded loaded-window resync on initial subscription and reconnect.
- Restricted translation cache hydration to IDs in each newly loaded page.
- Restricted live translation to bubbles with actual viewport visibility; pagination itself performs no LLM requests and cached rows still hydrate for the loaded page.
- Serialized visible live cache misses through one FIFO per chat; database-cached bubbles bypass the queue and at most one provider request is active.
- Made deterministic interface lanes server-owned, strengthened source/mode retry guidance for malformed short text, and set provider sampling to deterministic output so an inconsistent model response does not discard a valid translation.
- Added Supabase health reachability on network changes/send failures and offline-only recovery polling; unreachable sends remain pending and flush after recovery.
- Added a local 120-message history fixture command that places synthetic history before the translation cutoff.

Files/migrations/configuration changed:

- Updated chat service/state/screen, translation hydration state, connectivity state, and the direct HTTP dependency.
- Added focused pagination/realtime/reachability/translation tests and expanded the local Supabase replies integration test.
- Added `scripts/local_test.sh history [message-count]`; no schema migration was required.

Security/privacy review:

- Page queries and realtime filters continue to rely on existing chat-member RLS; no broader data access is introduced.
- Cached-translation hydration accepts only loaded message IDs and remains constrained by message/translation RLS.
- The health probe uses the public Supabase auth health endpoint without user data or secret headers; healthy clients do not poll continuously.
- The history helper signs in as the known local Alice fixture and targets only a local Alice/Bob chat.

Operational or documentation changes:

- Local manual QA can seed up to 500 pre-cutoff messages with `scripts/local_test.sh history`.
