## Finding confirmation

Current behavior:

- `blabRouter` sets `/dev` as the unconditional initial location.
- `/dev` is public and registered in every build mode.
- The development menu exposes forced offline and failed-send states plus a deliberate uncaught Sentry error.
- The startup widget test explicitly requires the development menu, preserving the release-blocking behavior.

Evidence:

- Audit: [`P0-01`](../../mvp-launch-audit-2026-07-15.md#p0-01-the-release-app-boots-into-a-public-development-menu)

- Initial/public route: `lib/app/router.dart:28-38`, `lib/app/router.dart:66-68`
- Release-exposed route: `lib/app/router.dart:120`
- Development controls: `lib/app/dev_menu.dart:9-118`
- Locked regression: `test/widget_test.dart:10-19`
- Deployed/release state: not reverified after implementation; the audit release build reproduced the development-menu startup

## Decision record

Required decision: `None. Production startup and developer-tool exclusion are explicit launch gates.`

Options and tradeoffs:

- Delete the development menu completely. This minimizes code but removes useful offline, failed-send, screen-state, and Sentry verification tools needed by later backlog items.
- Keep the route only when `kDebugMode` is true. This preserves deliberate development access while compile-time tree shaking excludes the route and menu from profile/release builds.

Approved decision: `Use the kDebugMode-only route. Normal startup never opens it; developers must navigate explicitly to /dev.`

Approved by/date: `Derived from the P0-01 launch gate and continued QA needs, 2026-07-16`

## Scope

In scope:

- Start normal launches at `/chats`; the existing auth redirect sends signed-out users to login while signed-in users remain on chats.
- Register and publicize `/dev` only in debug builds.
- Keep direct invite and auth recovery routes working as platform/default deep links.
- Replace the widget regression that expects the development menu with product-startup coverage.
- Verify a release artifact does not expose development-menu text or controls.

Out of scope:

- Preserve and resume invite state through authentication; tracked by L-03.
- Remove the underlying offline and failed-send providers; later messaging work still uses them for QA.
- Change authentication UI, account creation, or logout behavior.
- Configure release signing or Android App Links; tracked by L-04.

Files/systems expected to change:

- `lib/app/router.dart`
- `test/widget_test.dart`
- Focused router/startup tests if needed
- This work record and `tasks/launch/backlog.md`

Migration, rollout, or rollback concerns:

- No database migration is required.
- Existing sessions should open chats after upgrade; signed-out installs should open login.
- Rollback would re-expose internal controls and is not acceptable for a distributable build.

## Implementation record

Summary:

- Normal startup now targets `/chats`; the existing session-aware redirect sends signed-out users to login and leaves signed-in users on chats.
- `/dev` is included in the public-path set and route table only when Flutter's compile-time `kDebugMode` is true.
- The old startup regression now verifies the signed-out login journey, while a second test preserves explicit debug-menu access.
- The local Android helper accepts opt-in build-mode and initial-route overrides for repeatable debug/release route probes.

Files/migrations/configuration changed:

- `lib/app/router.dart`
- `test/widget_test.dart`
- `scripts/local_test.sh`
- `tasks/launch/local-testing.md`
- `tasks/launch/backlog.md`
- `tasks/launch/items/L-02.md`

Security/privacy review:

- A release user must not be able to trigger forced connectivity, failed-send simulation, or deliberate crash reporting.
- Compile-time debug gating is required; hiding a visible button alone is insufficient.

Operational or documentation changes:

- Debug QA starts the menu explicitly at `/dev`; normal debug startup follows the product journey.
- `BLAB_FLUTTER_MODE` supports `debug`, `profile`, and `release`; `BLAB_INITIAL_ROUTE` supplies deliberate route probes to the local helper.
