## Finding confirmation

Current behavior:

- The composer attaches `replyTo` only to the optimistic local bubble. The send service omits the existing `messages.reply_to` column, retry persistence stores no stable reply ID, and history/Realtime mappers ignore the relationship. The quote therefore disappears after canonical reconciliation or reopen.
- `reply_to` is a single-column foreign key and does not require the target to belong to the same chat.
- L-08 already enforces sender ownership, membership, immutable fields, server-owned `edited_at`, and the 24-hour edit window in PostgreSQL.
- The action sheet still offers Edit for every outgoing bubble, including messages older than 24 hours and unsent rows.
- Translation state is keyed only by message ID and language, so an edited body can continue displaying the previous in-memory translation. Persisted translations are not invalidated when the source body changes.

## Decision record

Required decision: `None.` The PRD explicitly approves replies, a 24-hour edit window, deletion forever, and an edited marker.

Options and tradeoffs:

- Use the existing `messages.reply_to` relationship rather than duplicating quote text. This preserves one source of truth and avoids retaining deleted message content in a snapshot.
- Resolve reply targets from fetched/streamed message rows. Deleted targets use a neutral placeholder instead of exposing deleted body text.
- Keep PostgreSQL as the authoritative edit-window boundary and mirror it in the action sheet. Client clock skew can only hide/show an action; the server still decides whether an edit succeeds.

Approved decision: Wire the existing foreign key end to end, constrain it to the same chat, and mirror the already-approved database edit contract in the client.

Approved by/date: Existing approved product requirements, confirmed `2026-07-17`.

## Scope

In scope:

- Persist `reply_to` for online, offline, automatic retry, manual retry, and idempotent duplicate-send paths.
- Preserve stable reply target identity in account-scoped pending storage.
- Reconstruct reply quotes from history and Realtime snapshots, including a non-sensitive placeholder when the target was deleted.
- Reject self-replies and cross-chat reply targets at the database boundary.
- Show Edit only for delivered outgoing messages within 24 hours; keep Delete available forever.
- Preserve edit mode and show an error when the server rejects an edit.
- Invalidate persisted and in-memory translations after a source-message edit.

Out of scope:

- History pagination and replies to targets outside the loaded/streamed history; L-16 owns pagination.
- Translation authorization, quotas, provider routing, and race-proof cache versioning; L-13 owns those controls.
- Reply navigation/scroll-to-source, nested reply rendering, reactions, or message UI redesign.

Files/systems expected to change:

- Chat service, mapper, state, pending-send persistence, action sheet/screen, focused tests, and one Supabase migration.

Migration, rollout, or rollback concerns:

- Existing invalid cross-chat/self-reply rows must be nulled before adding constraints.
- Pre-L-10 queued replies have no stable target ID and are discarded during hydration instead of being silently sent as ordinary messages.
- New clients remain compatible with nullable `reply_to`; old clients continue sending non-replies.
- Rolling back the client leaves stored reply IDs harmless. Rolling back the migration removes added integrity/cache triggers only.
